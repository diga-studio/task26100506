# device_health — 设备健康时长统计库

Python 库，供本地管理程序调用，明细数据保存在 SQLite。统计每台设备当前健康
状态及最近 30 天各健康等级的累计秒数，支持乱序、重复、迟到的补传心跳。

## 业务规则

- 业务时间 `T` 从 0 秒开始，只能前进；所有时间均为整数秒，调用方保证采样
  时间不晚于 `T`。
- 心跳含设备标识、采样时间、CPU 利用率、内存利用率、磁盘剩余比例（均为
  百分比数值 0-100）。同设备同采样时间视为同一条心跳，重复提交自动去重。
- 一条心跳自采样时刻起生效，直到下一条心跳生效或经过 1800 秒（以较早者
  为准，恰好 1800 秒即失效）。生效期间：磁盘剩余 < 10% 为 `Critical`；
  否则 CPU 或内存 > 85% 为 `Warning`；其余为 `Healthy`。无有效心跳时
  为 `Critical`。
- 报告区间为 `[max(0, T-2592000), T)`，含起点、不含 T；三个等级累计秒数
  之和恒等于区间长度。采样时间恰为 T 的心跳影响当前健康但不贡献时长。
- 早于窗口起点的补传直接忽略；窗口起点及其之后的补传会修正历史时长。
  最终结果只取决于有效心跳的采样时间与内容，与到达顺序、重复次数无关。

## 调用说明

```python
from device_health import DeviceHealthStats, Heartbeat

stats = DeviceHealthStats("health.db")   # 打开/创建 SQLite 库，恢复业务时间

# 1) 提交一批心跳（可乱序、可重复），返回实际新增条数
stats.submit([
    Heartbeat(device_id="srv-1", ts=0,    cpu=50, mem=50, disk_free=50),
    Heartbeat(device_id="srv-1", ts=600,  cpu=90, mem=50, disk_free=50),
    Heartbeat(device_id="srv-1", ts=2700, cpu=50, mem=50, disk_free=50),
])

# 2) 推进业务时间并清理过期明细（只能前进）
stats.advance(3600)

# 3) 查询单设备当前健康及最近 30 天各等级累计秒数
report = stats.query("srv-1")
# {
#   "device_id": "srv-1", "now": 3600, "window_start": 0,
#   "current": "Healthy",
#   "durations": {"Healthy": 1500, "Warning": 1800, "Critical": 300},
# }

stats.close()                            # 也可用作上下文管理器
```

仅以上三类操作（`submit` / `query` / `advance`）。调用串行，不支持并发。

## 设计要点

- **存储**：SQLite 单表 `heartbeats(device_id, ts, level)`，主键
  `(device_id, ts)` 天然去重；业务时间存于 `meta` 表，重开库后恢复。
- **内存索引**：每设备维护按采样时间分块（sqrt 分解，块约 512 条）的有序
  结构，每块缓存三等级贡献秒数。单条补传只重算相邻两块（O(块大小)），
  查询合并整块缓存 + 两端部分块逐条裁剪（O(块数 + 块大小)）。大批量
  提交自动切换为合并重建（O(n)）。
- **清理**：`advance` 时删除 `ts <= 窗口起点 - 1800` 的明细（SQLite 与
  内存同步删除）。窗口起点前 1800 秒内的心跳在窗口内仍可能有贡献，必须
  保留；被删除的明细对窗口贡献恒为 0，报告不会失真。SQLite 复用被释放
  的页，持续运行中每个 30 天周期数据量相同时存储占用趋于稳定。

## 测试

```bash
python3 -m pytest tests/ -q          # 全部测试（含规模实测）
python3 -m pytest tests/test_performance.py -q -s   # 查看实测数据
```

- `tests/test_correctness.py`：验收用例（顺序/乱序/重复一致性、给定数值
  用例 1500/1800/300 与 2400/1200/0、窗口起点前 900 秒心跳、TTL 恰到期、
  T 时刻心跳、清理不变性、持久化重开等），以及 3 万条心跳与朴素算法的
  精确对拍。
- `tests/test_performance.py`：规模与性能实测。

## 规模实测结果（本机，Python 3.14）

| 指标 | 要求 | 实测 |
| --- | --- | --- |
| 初始加载 1,000,000 条心跳（10000 台设备，含建库） | — | 1.83 s |
| 高密度设备（20 万条）1000 次补传 + 紧接查询累计 | ≤ 20 s | 0.22 s |
| 单次查询 p95 | ≤ 200 ms | 0.07 ms（max 0.23 ms） |
| 清理后存储占用（5 个 30 天周期，每周期数据量相同） | 趋于稳定 | 稳定于 20.2 MB |

规模下重复提交新增条数为 0、报告不变，三项时长之和恒等于窗口长度
（精确到秒）。
